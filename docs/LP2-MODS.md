# Lost Planet 2: online play and mod loader

A Lost Planet 2 build of [xlive-steamworks](https://github.com/sokie/xlive-steamworks) by
**sokie** (MIT). sokie's `xlive.dll` replaces Games for Windows Live with Steamworks so LP2's
multiplayer works again. This build adds a mod loader on top: quality-of-life options, extra
maps and custom character parts.

> **Status: work in progress, not released.** Map packages and hold-to-zoom work in game.
> Custom parts export from Blender but are not loaded by the game yet, and nothing is synced
> between players yet. The roadmap is at the end.

---

## Install

1. Find the game folder (Steam → Lost Planet 2 → Manage → Browse local files).
2. Back up `xlive.dll` (e.g. rename it to `xlive.dll.capcom`).
3. Unzip the release into that folder. `xlive.dll` sits next to `LP2DX11.exe`.
4. Play the **DirectX 11** version (`LP2DX11.exe`). The mods target it, and it uses memory far
   better (see Memory).

A Steam "Verify integrity of game files" or a game update puts Capcom's `xlive.dll` back.
Re-copy ours afterwards.

### Memory: Large Address Aware (recommended)

LP2 is 32-bit and only uses 2 GB unless the exe is marked Large Address Aware (LAA), which raises
it to 4 GB. Custom maps and parts need the headroom.

| System | How |
|---|---|
| Linux / Steam Deck (Proton) | Launch option: `WINE_LARGE_ADDRESS_AWARE=1 %command%` |
| Windows | Run the LAA patcher on your own `LP2DX11.exe` (planned; re-run it after Steam verifies or updates the game) |

The limit is address space, not RAM or VRAM. With the DX9 exe, textures usually take room both
in VRAM and inside the 4 GB; with DX11 they mostly stay in VRAM.

## Folder layout

Everything lives in the game folder, next to the exe:

```
Lost Planet 2\
├─ LP2DX11.exe              (the game, untouched)
├─ xlive.dll                this build
├─ steam_api.dll            Valve's Steamworks library
├─ xlive_steamworks.json    settings (optional; every key has a default)
├─ xlive_steamworks.log     log, written on every start
├─ Mods\                    file-replacement mods: folders or .zip
├─ Maps\                    map packages: .zip
├─ Parts\                   custom part sets: folders or .zip
└─ ModCache\                generated by the loader; safe to delete, never share it
```

The folder locations can be changed in the settings (`mods.dir`, `maps_dir`, `parts_dir`, `cache_dir`).

## Settings (`xlive_steamworks.json`)

Comments are allowed. Mod-related keys:

```jsonc
{
	"mods": {
		"disabled": ["SomeMod"],  // Mods\ entries to skip (folder or zip name without .zip)
		// "enabled": [...],      // or: only these Mods\ entries, in this order (later ones win)
		"trace_opens": 0,         // debugging: log the first N files the game opens
		"parts_any_faction": false // true: every part (stock and custom) can be picked by every faction
	},
	"log": { "level": "info" }   // debug / trace for troubleshooting
}
```

## Plugin mods (code)

xlive.dll itself only adds networking and mod support; gameplay and quality-of-life changes are
plugin mods, so the game stays as vanilla as you want. A plugin mod is a normal Mods\ entry with a
.dll at its top level (contract: `sdk/lp2mod.h`); delete the folder or list it in
`mods.disabled` to turn it off.

| Mod | What it does | Settings | Status |
|---|---|---|---|
| `Mods\SkipSplash` | Skip the boot logos, straight to the title screen. | none | Works (was built in) |
| `Mods\DevTools` | Testing aids: `solo_start` (host a Player Match alone and play it) and `game_log` (the game's debug messages in the log, DX11). | `devtools.json` | Works (was built in) |
| `Mods\Controls` | Hold to aim (zoom only while held, on foot) and split on-foot / VS controls: in a VS an action can take the button of another action (keyboard, mouse and pad) or any key / mouse button (`"key:F"`, `"key:MOUSE_X1"`). Foot actions: jump, grapple, next_weapon, crouch, fire, grenade, reload, action, quick_turn, zoom, melee, gesture, teng, dodge; VS: fire, secondary (= grenade button), zoom, brake, reload, quick_turn, dash, boost. | `controls.json` | Hold to aim works (DX11); split controls untested |
| Key config menu (in Controls) | The Controls page is regrouped under Shared / On Foot / Scoped / VS / Flying VS headers, with Hold to aim ON/OFF and VS Secondary / Zoom / Get out and Ascend / Descend key rows (Esc cancels, Delete resets to the game's key). | saved to `controls.json` | Works (DX11) |

The old `mods.skip_splash`, `hold_zoom`, `solo_start` and `game_log` settings are ignored (a warning in the log says so).

## Mods\ (file replacement)

Each entry is a folder or a `.zip` whose files mirror the game folder:

```
Mods\
└─ BetterHUD\              (or BetterHUD.zip)
   └─ nativePC\...          same relative paths as the game's own files
```

When the game opens a file, the loader serves the mod's copy if one exists. Mods load
alphabetically (or in `enabled` order) and later ones win. Nothing in the game folder is changed.

## Maps\ (map packages)

`Maps\<Name>.zip` containing:

```
map.json                  {"name": "Test Arena", "size": "medium", "base": 0, "number": 0}
nativePC\...              the map's files, built for online map <number>
```

| Key | Meaning |
|---|---|
| `name` | Name shown in the map picker |
| `size` | `small` / `medium` / `large`: lobby size class and which Random pool it joins |
| `base` | Online map whose vehicles, weapons and objects it preloads |
| `number` | The online map number its files were built for (renumbered automatically) |

The game has two free map numbers (13 and 14), so **two map packages at a time for now**.
Mapping more packages onto those slots per session is planned.

## Parts\ (custom character parts)

Drop the exporter's `LPC_<id>` folder in as is, or zip it:

```
Parts\
└─ LPC_scav01\             (or LPC_scav01.zip)
   ├─ lpc.json              {"id", "name", "faction", "colours", "parts": {"body": {"file", "template"}, ...}}
   ├─ body.rModel
   ├─ head.rModel
   ├─ back.rModel
   └─ legs.rModel           any subset of the four
```

Factions: `RND` Rounders, `FJ` Fight Junkies, `SPE` Snow Pirate Elites, `NEV` NEVEC Black Ops,
`FF` Femmes Fatales, `ALL` everyone.

`colours` (optional, default `"A"`): the colour letters the set offers, e.g. `"ACD"` or
`["A", "C"]`. With two or more, players step through them on the part's swatch like a stock part;
with one, the swatch is locked. Each letter wears the part's own colour map for it, else its `_A`,
else the template part's. The choice is remembered per set and part in `ModCache\parts\colours.txt`.
(Older `"colour": "B"` still works: that colour only.)

Each colour can also have its own shine: a part's `textures` may add `MM_<letter>` / `NM_<letter>`
(that colour's mask / normal map) and `material_overrides` per colour (`spec_power`,
`spec_colour`); see `README-parts.md` §9 "Shine per colour".

**How they appear:** at start, each part of each set is built into a small DLC content package in
`ModCache\parts\pkg\` (the template part's archives with the custom model in place; rebuilt only
when something changes) and listed in each category's part list under the set's name, after the
stock parts. Sets take DLC slots from 20 upward in `id` order (50 sets at most for now), and the
loader keeps them unlocked in the profile, so a fresh save sees them too.

Limits for now: colours are remembered per set and part (not per loadout), and everyone in a match needs the same
`Parts\` content (see Multiplayer rules). Making parts: `README-parts.md` in the creator tools.

## Troubleshooting

- **Logs:** `xlive_steamworks.log` next to the exe. Each map package, part set and mod patch logs
  a line saying whether it loaded or why it was skipped.
- **Mods don't apply:** the mods match the current Steam build of the exe and check its code before
  patching. On a different build they skip themselves (logged) instead of crashing.
- **Odd behaviour after editing a package:** delete `ModCache\`; it is rebuilt on the next start.

## Multiplayer rules

- Everyone in a match should run the same release.
- Custom maps and parts will be sent to players who don't have them, in the lobby before the
  match (planned). Until then, everyone needs the same `Maps\` and `Parts\` content.
- Hitboxes are shared by every human and never change with parts.

## Distribution

What a release contains, and what it must never contain:

| Ship | Never ship |
|---|---|
| `xlive.dll` (this build) | any game file: exes, `.arc` archives, anything from `nativePC` |
| `steam_api.dll` (Valve redistributable) | `ModCache\` (generated per machine) |
| `xlive_steamworks.json` (example settings) | `xlive.dll.capcom` / backups |
| empty `Mods\`, `Maps\`, `Parts\` (+ demo content) | packages containing copies of Capcom's files |
| `LICENSE` (MIT) + credits to sokie | a pre-patched (LAA) exe |
| this guide, the LAA patcher (Windows) | |

Planned bundle:
- **Player release:** the loader, settings with the QOL options, one demo map and a few demo
  part sets.
- **Creator kit (separate):** the Blender importer and exporter, `lp2model.py`, packaging scripts
  and `README-parts.md`.

Demo content must be original or reference the game's own files by path. Shipping copies of
game files, like the Test Arena prototype's copied Desecration archives, is not allowed.

## Roadmap

1. Custom parts in game (first through a DLC slot for testing, then the carrier loader).
2. Textures and skins for parts (colour variants, reusing game textures by reference).
3. Sending maps and parts to other players in the lobby.
4. Split on-foot / VS / scoped controls.
5. More than two map packages per session.
6. Windows LAA patcher; a raised player cap later.
